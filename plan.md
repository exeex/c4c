# RV64 Byval Prepared Call Boundary Runbook

Status: Active
Source Idea: ideas/open/659_rv64_byval_prepared_call_boundary.md

## Purpose

Turn the probe-first byval/prepared call-boundary follow-up into small,
evidence-led execution steps.

## Goal

Repair the first proven boundary where prepared byval aggregate facts, pointer
argument preservation, formal GPR publication, or RV64 call lowering disagree.

## Core Rule

Do not make a named-case or final-assembly-shape fix. Every code-changing step
must publish or consume explicit prepared call-boundary facts for source
payload, destination home, and call ABI ownership.

- Do not reopen the idea 657 `loop-2e.c` representative writeback route.
- Do not merge AArch64 dispatch, CLI dump formatting, LLVM torture owner

  offset work into this route.
- Do not edit expectations, unsupported markers, allowlists, timeout settings,
  runtime policy, or baseline acceptance files.

## Working Model

The current classification marks all nine rows as `blocked pending probe`.
Start by refreshing evidence across dump, route, runtime, and object-runtime
surfaces. Only after the first owner is proven should implementation begin.

Potential first-owner boundaries are:

- prepared call-boundary publication for pointer arguments and byval payloads
- byval aggregate source or destination copy facts
- formal GPR publication for byval callees
- RV64 consumption of already-published call-boundary facts

## Execution Rules

- Keep routine executor progress in `todo.md`.
- Use Step 1 to record focused evidence before changing code.
- Keep implementation slices narrow to one proven owner.
- Add or update focused backend proof only for the selected owner.
- Run build or compile proof before treating any code slice as complete.
- Use `test_after.log` as the executor proof log unless the supervisor
  delegates a different artifact.
- Escalate to reviewer or plan-owner if evidence splits this family into a
  smaller first-owner route.

## Ordered Steps

### Step 1: Refresh Focused Byval Evidence

Goal: prove the first broken byval/prepared call-boundary owner before any code
change.

Primary targets:

- `tests/backend/CMakeLists.txt`
- the nine target test cases listed in `Current Targets`
- relevant prepared-BIR dumps, route assembly outputs, and runtime/object
  runtime diagnostics generated by those tests

Actions:

- Run or inspect the focused target subset under the supervisor-delegated proof
  command.
- Compare dump, route, runtime, and object-runtime failures for the fixed
  byval aggregate, preserved pointer args, formal GPR publication, and
  frame-slot pointer-arg payload rows.
- Identify whether the earliest failing boundary is producer publication,
  byval copy planning, formal publication, or RV64 consumption.
- Record evidence in `todo.md`, including any smaller split if the nine rows
  do not share one first owner.

Completion check:

- `todo.md` names one selected first owner, or records a smaller split with
  concrete row evidence.
- No implementation, test expectation, unsupported-marker, allowlist, runtime
  policy, or baseline acceptance file is changed.

### Step 2: Repair The Selected Publication Or Consumption Boundary

Goal: implement the smallest semantic repair for the owner proven in Step 1.

Primary targets:

- the prepared call-boundary publication path if producer facts are missing or
  stale
- the byval aggregate source/destination copy path if copy facts are wrong
- the formal GPR publication path if callee formal facts are missing
- the RV64 call-lowering/object-runtime consumer if explicit facts are present
  but ignored

Actions:

- Modify only the files required for the selected owner.
- Preserve existing pass cases outside the selected byval/prepared
  call-boundary surface.
- Prefer explicit prepared facts over inference from testcase names, local
  variable names, or final assembly shape.
- Add diagnostics or fail-closed checks when facts are ambiguous instead of
  silently choosing a testcase-shaped path.

Completion check:

- The selected owner publishes or consumes explicit facts for source payload,
  destination home, and ABI ownership.
- The focused build/proof command passes for the changed owner or fails closed
  with precise diagnostics that identify the remaining boundary.

### Step 3: Prove The Focused Target Subset

Goal: show the repair improves the byval/prepared call-boundary surface without
moving failures into adjacent families.

Primary proof command:

```sh
ctest --test-dir build -j --output-on-failure -R 'backend_(dump_riscv64_byval_aggregate_fixed_call|codegen_route_riscv64_byval_aggregate_fixed_call|dump_riscv64_byval_preserved_pointer_args|codegen_route_riscv64_byval_preserved_pointer_args|codegen_route_riscv64_byval_formal_gpr_publication|rv64_runtime_riscv64_byval_aggregate_fixed_call|rv64_runtime_riscv64_byval_preserved_pointer_args|rv64_runtime_riscv64_byval_formal_gpr_publication|obj_runtime_rv64_frame_slot_pointer_arg_preserves_payload)'
```

Actions:

- Run the focused subset after the implementation slice.
- Check nearby byval aggregate, pointer call-boundary, and formal-publication
  rows that may share the same owner when the diff touches shared helpers.
- Record the proof command and result in `todo.md`.

Completion check:

- The focused byval/prepared call-boundary subset passes, or any remaining
  failure has a precise proven owner and is not hidden by an expectation or
  unsupported-marker change.

### Step 4: Broader Backend Regression Check

Goal: verify the accepted route does not regress broader backend behavior.

Actions:

- Ask the supervisor for the required broad proof scope if not already
  delegated.
- Prefer a backend subset such as:

```sh
ctest --test-dir build -j --output-on-failure -R '^backend_'
```

- Preserve canonical regression-log discipline: root-level broad logs are
  `test_before.log` and `test_after.log` only when the supervisor delegates a
  regression guard run.

Completion check:

- Backend regression proof shows no new backend failures in the delegated
  subset.
- `todo.md` records the proof result and any residual rows that belong to a
  separate idea rather than this byval/prepared call-boundary route.
