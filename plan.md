# LIR Memory, VA, Object, and Lifetime Authority Runbook

Status: Active
Source Idea: ideas/open/867_lir_memory_va_object_lifetime_authority.md

## Purpose

Publish one exact typed LIR producer/schema authority route for a remaining
memory, variadic-argument, object, or lifetime fact so 734 can later receive
one bounded typed row without display-text recovery.

## Goal

Select, implement, verify, and hand off exactly one native
memory/VA/object/lifetime authority fact.

## Core Rule

This source is first-owner LIR producer/schema/verifier work only. Do not edit
Raw-BIR receiver/importer code, reopen accepted local-object/VLA/memcpy rows,
or recover facts from operand spelling, printer output, LLVM text, rendered
names, or testcase identity.

## Current Scope

- Choose one bounded current LIR fact gap from the memory/VA/object/lifetime
  family.
- Add native LIR fields or schema carriers only for that selected fact.
- Populate the carrier at its exact producer seam.
- Verify current-function ownership, validity, type or object/lifetime
  suitability, and malformed rejection for that fact.
- Produce a handoff document naming the exact future 734 receiver row.

## Non-Goals

- No Raw-BIR receiver, importer, builder, or dispatcher implementation.
- No broad memory, pointer, object, lifetime, stack, or VA sweep.
- No accepted local-object, VLA stack-save/restore, or selected memcpy receipt
  rewrite.
- No aggregate/vector, CFG/PHI, body-parameter, inline-assembly template,
  global policy, or terminal 797 convergence work.
- No expectation downgrade, unsupported-marker change, allowlist filtering, or
  named-test shortcut.

## Working Model

The first executable work is evidence-driven selection. If tracing shows the
candidate row is already accepted, is Raw-BIR-only, or needs a different first
owner, stop and repair lifecycle instead of forcing it into 867. The accepted
output must be a typed LIR handoff, not a receiver implementation.

## Execution Rules

- Keep each implementation step bounded to the one selected seam.
- Preserve existing accepted rows as historical evidence only.
- Add same-feature positive and malformed/foreign/mismatch verifier coverage
  near the selected producer/verifier path.
- Keep compatibility mirrors check-only; never parse rendering as semantic
  state.
- For code-changing steps, run a fresh build plus focused producer/verifier
  proof. Escalate to a broader proof if shared LIR schema or verifier helpers
  are touched.

## Ordered Steps

### Step 1 - Select the bounded authority seam

Goal: identify exactly one memory/VA/object/lifetime fact that needs native LIR
producer/schema authority.

Actions:
- Trace current memory, VA, object, and lifetime LIR producers and verifier
  checks relevant to the remaining 866 family.
- Exclude accepted local-object, VLA stack-save/restore, and selected memcpy
  receipt history.
- Choose one seam with a concrete producer, expected native facts, owner/type
  checks, and future 734 receiver row.
- Record in `todo.md` the selected seam, files to inspect next, and focused
  proof candidate.

Completion check:
- One bounded seam is named with its current gap and exact in/out boundary.
- No code changes are needed for this step unless tracing requires a small
  diagnostic-only adjustment approved by the supervisor.

### Step 2 - Publish the selected native LIR authority

Goal: add the native carrier and producer population for the selected fact.

Actions:
- Add the smallest LIR field, schema carrier, or typed authority structure that
  represents only the selected fact.
- Populate it at the exact producer seam.
- Keep stale/text/compatibility fields non-authoritative and fail closed.
- Avoid changing Raw-BIR receivers or unrelated producer families.

Completion check:
- The selected positive route carries native current-function authority without
  display-text recovery.
- Fresh build passes.

### Step 3 - Verify and cover malformed authority

Goal: enforce the selected carrier contract and prove rejection boundaries.

Actions:
- Add verifier checks for current-function ownership, value/object validity,
  type or object/lifetime suitability, and malformed/foreign/mismatch cases
  that apply to the selected seam.
- Add nearby positive and negative tests for the exact selected authority.
- Keep previously accepted local-object, VLA, and selected memcpy tests valid
  without weakening or repurposing them.

Completion check:
- Focused same-feature producer/verifier proof passes.
- Matching malformed/foreign/mismatch cases fail for authority reasons, not
  presentation parsing or named-case filtering.

### Step 4 - Write the 734 handoff and prove the route

Goal: deliver one exact typed handoff for later 734 receiver work.

Actions:
- Create or update a handoff document under an appropriate `docs/` directory
  naming the exact LIR fields, owner checks, accepted positive case, rejected
  malformed cases, and one future 734 receiver row.
- Run `git diff --check`.
- Run the accepted proof ladder: fresh build, focused producer/verifier proof,
  and broader LIR/frontend/backend subset if the implementation touched shared
  schema or verifier paths.
- Update `todo.md` with proof commands and the precise 734 return condition.

Completion check:
- Handoff document and proof establish exactly one future 734 receiver row.
- No Raw-BIR receiver work landed in this idea.
