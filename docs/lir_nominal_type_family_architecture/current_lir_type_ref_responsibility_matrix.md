## Exhaustiveness and ownership rules

Every `LirTypeRef` field reported in `ir.hpp` is covered by one of M1--M10 or
the linked global/function group M15; every constructor/factory and public
escape hatch is in M1--M4, M11, or M16; every named verifier, printer, call
compatibility, collector, and receiver surface is M9 or M12--M15.  Runtime text
is not a generic disposition: M11 names each producing factory, M8/M9 name raw
call/signature adapters, M14 names collector fallbacks, and M15 names
global/extern consumers.  Intentional final rendering is permitted only as
one-way output, never input to semantic identity.

Rows M4--M7 recursively require their children to be family refs.  An outer
array, vector, aggregate, or signature is not migrated while an element,
field, nested aggregate, return, or parameter remains text-primary.  Existing
open ideas remain dependencies only; no row duplicates 734, 795, 797,
829--831, 836, 812, or 813.
