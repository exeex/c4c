## Coverage and routing constraints

The rows above cover the required families: all `LirTypeRef` construction,
classification and mutation escapes; raw and parsed call arguments/returns,
suffixes and scans; module/global/extern/function/struct shadows; global
policy/initializer/name concerns; expressions/operands/coercions; parameters
and ABI; residual instructions/intrinsics/CFG/PHI/asm; aggregate/vector;
intrinsic text; and LIR-to-new-BIR receipts.  Exact declaration ranges are
included in each relevant row so a later Step 3 handoff can select only rows
whose disposition is `unowned semantic route` or `insufficient evidence`.

No row treats text as authority merely because it is a string.  Conversely,
the `existing open owner` and `insufficient evidence` rows identify every
remaining semantic parser, classifier, mutation, scan, or receiver seam rather
than masking it as intentional text.
